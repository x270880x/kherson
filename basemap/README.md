# basemap/ — локальные тайлы подложки

⚠️ Не путать с `tiles/` — там векторные тайлы участков (`.pbf`), которыми рисуется карта.
Здесь растровая подложка под ними.

| папка | источник | зумы | файлов |
|---|---|---|---|
| `sat/{z}/{x}/{y}.jpg` | Esri World Imagery | 9–13 | 3 607 |
| `osm/{z}/{x}/{y}.png` | OSM France (osmfr) | 9–13 | 3 607 |

**Почему только обзорные зумы.** Официальные серверы OpenStreetMap отдают нам 403
«App is not following the tile usage policy», из-за чего карта превращалась в стену плиток
«Access blocked». Для с. Бухта проблему решили, скачав всю подложку целиком, но здесь область:
613 471 полигон, и покрытие до рабочего z18 — это 3,1 млн плиток и ~45 ГБ. Не влезает ни в
лимит GitHub Pages (1 ГБ на сайт), ни в разумное число запросов к чужим серверам.

Поэтому локально лежат только обзорные зумы z9–13 (78 МБ) — общий вид области открывается
со своего сервера. Детальные зумы берутся с внешних источников: `localTiles()` в index.html
подставляет удалённый URL, если локального тайла нет.

**Спутник заканчивается на z18.** Проверено по Херсону, Геническу, Новой Каховке и Скадовску:
на z19 Esri отдаёт серую плитку «Map data not yet available». В слоях выставлен
`maxNativeZoom` (18 снимок / 19 схема), `maxZoom: 21` — Leaflet растягивает последний
настоящий тайл вместо запроса несуществующего.

Обновить: `scratchpad/fetch_kherson.py` (через curl — urllib в Python 3.14 не проверяет
сертификаты). Уже скачанные файлы пропускаются.
